# ความคืบหน้าเครื่องมือสแกนเอกสารเป็น PDF

อัปเดต: 19 ตุลาคม 2569

## ขั้นที่ 1 — ทางเข้าและหน้าจอพื้นฐาน

- เพิ่มการ์ดสแกนเอกสารเป็น PDF เป็นเครื่องมือที่สอง
- แยกสถานะเครื่องมือที่เลือกเป็นกระดาษคำตอบ/สแกนเอกสาร
- เปิดเครื่องมือสแกนได้โดยไม่ต้องสร้างพื้นที่ข้อมูลห้องเรียน
- เพิ่มหน้าเริ่มต้นและแถบขั้นตอน เพิ่มเอกสาร → ปรับและจัดหน้า → ดาวน์โหลด
- ปุ่มกลับหน้าเลือกเครื่องมือใช้งานได้ และถอด component ของสแกนออกเมื่อกลับ
- หน้าตาปรับตามขนาดหน้าจอ มีชื่อหน้าสำหรับเครื่องมือและย้าย focus ไปหัวข้อเมื่อเปิด

ขอบเขตเมื่อจบขั้นที่ 1: ปุ่มถ่ายและเลือกรูปยังปิดไว้ พร้อมข้อความระบุว่าเป็นหน้าจอตัวอย่าง ยังไม่มีภาพหรืองานสแกนให้จัดเก็บหรือล้าง วงจรข้อมูลภาพชั่วคราวจะทำพร้อมการนำเข้าในขั้นที่ 2

ตรวจแล้ว: TypeScript ผ่าน, build สำหรับ GitHub Pages ผ่าน และลองเปิดเครื่องมือใหม่ → กลับหน้าเลือกเครื่องมือ → เปิดกระดาษคำตอบเดิมผ่านเบราว์เซอร์ตัวอย่างในเครื่องแล้ว

build มีคำเตือนเรื่องเส้นทางฟอนต์และขนาดไฟล์ ExcelJS ของโปรเจกต์ ยังไม่ได้ตรวจออฟไลน์หรือกล้องบนโทรศัพท์จริง

## ขั้นที่ 2 — นำเข้าภาพและจัดหน้า

- ใช้ภาพการ์ดแบบ A สีฟ้าทั้งกระดาษคำตอบและสแกน PDF ตามที่ผู้ใช้เลือก
- เปิดปุ่มถ่ายเอกสารผ่านกล้องของอุปกรณ์ และเลือกรูปหลายไฟล์
- นำเข้าทีละภาพพร้อมสถานะ หากภาพใดเปิดไม่ได้แจ้งชื่อและนำเข้าภาพอื่นต่อ
- เก็บไฟล์ต้นฉบับกับภาพตัวอย่างด้านยาวไม่เกิน 1,600 พิกเซลในหน่วยความจำ
- เลือกภาพย่อ ดูภาพใหญ่ หมุนครั้งละ 90 องศา ลบ และเรียงลำดับด้วยปุ่มหรือลากภาพย่อ
- ถามก่อนออกและล้างงาน มีปุ่มทำต่อ และขอคำเตือนรีเฟรชจากเบราว์เซอร์เมื่อรองรับ
- คืน object URL และทิ้งผลนำเข้าที่กลับมาหลังปิดเครื่องมือ

ตรวจในเบราว์เซอร์ตัวอย่างแล้ว: เลือกหลายภาพพร้อมไฟล์ PNG เสียยังได้ภาพที่ใช้ได้ครบ หมุนแล้วภาพและลำดับถูกต้อง ลบหน้าที่เลือกแล้วแสดงหน้าที่เหลือ กดทำต่อแล้วภาพยังอยู่ และออก/เปิดใหม่แล้วไม่มีภาพค้าง

TypeScript และ build ผ่าน ตรวจ lint โมดูลสแกนผ่าน ส่วนหน้าเลือกเครื่องมือใช้ภาพ `<img>` ตามระบบ Vite เดิมและมีคำเตือนจากกฎ Next.js ยังไม่ได้ตรวจการเปิดกล้องบน iPhone/Android จริงหรือการลากภาพย่อด้วยเมาส์

## ขั้นที่ 3 — ปรับขอบและแก้มุมกระดาษ

- เปิดปรับขอบจากหน้าที่เลือก ลากมุม 4 จุดด้วยเมาส์/นิ้ว และปรับละเอียดด้วยปุ่มลูกศร (Shift เพื่อเลื่อนมากขึ้น)
- ป้องกันกรอบไขว้ พื้นที่เล็กเกินไป และมุมออกนอกภาพ
- แก้มุมมองกระดาษจากภาพต้นฉบับด้วยการแปลง perspective และเกลี่ยพิกเซลระหว่างตำแหน่ง
- เก็บกรอบของแต่ละหน้าไว้ แก้ไขซ้ำ ยกเลิก และคืนกรอบเต็มภาพได้ โดยคงการหมุนเดิม
- เพิ่มปุ่มจับขอบอัตโนมัติ เหมาะกับกระดาษสว่างบนพื้นหลังที่ตัดกัน หากไม่มั่นใจจะแจ้งให้ลากมุมเองและคงกรอบเดิมไว้
- ใช้ worker แยกในการหาขอบและแก้มุม มีสถานะระหว่างประมวลผลและหยุดงานเมื่อปิดหน้าต่าง
- แยกภาพต้นฉบับกับภาพหลังปรับ พร้อมคืน URL ของภาพที่เลิกใช้

ตรวจแล้ว: ทดสอบ 3 กรณีผ่าน (แก้มุมสี่จุดโดยไม่กลับด้าน, ปฏิเสธกรอบไม่ถูกต้อง, จับขอบพื้นหลังตัดกันและปฏิเสธภาพขาวล้วน) พร้อม TypeScript, lint และ build

ลองผ่านเบราว์เซอร์แล้ว: จับขอบภาพเอกสารเอียงจำลอง ลากมุมด้วยเมาส์โดยตำแหน่งภาพไม่ขยับ ใช้ปุ่มลูกศรแก้มุม บันทึกผล กลับมาแก้ไข ยกเลิกแล้วผลเดิมยังอยู่ และคืนภาพต้นฉบับได้ การตรวจจับอัตโนมัติยังต้องทดลองเอกสารถ่ายจริงหลายพื้นหลังและสภาพแสง รวมถึงการลากด้วยนิ้วบนโทรศัพท์จริง

## ขั้นที่ 4 — โหมดภาพ

- เพิ่มสีเดิม ขาวดำ (ระดับสีเทา) และขาวดำคมชัด (แยกพื้นกับตัวอักษรตามแสงในแต่ละบริเวณ)
- เลือกโหมดเฉพาะหน้า และใช้โหมดของหน้าที่เลือกกับทุกหน้าที่มีอยู่ได้
- ภาพย่อระบุโหมดของแต่ละหน้า และเปลี่ยนตามภาพตัวอย่างจริง
- เก็บภาพสีหลังปรับขอบแยกจากภาพแสดงผล เปลี่ยนโหมดซ้ำแล้วไม่ใช้ภาพที่ผ่านฟิลเตอร์แล้วเป็นต้นทาง
- แก้ขอบแล้วคงโหมดและการหมุนไว้ กลับสีเดิมแล้วได้ภาพสีก่อนปรับโหมด
- ใช้ worker ประมวลผลทีละหน้า พร้อมสถานะและปุ่มยกเลิก ถ้ายกเลิกหรือล้มเหลวจะคงค่าทุกหน้าไว้เหมือนก่อนเริ่ม
- คืน URL ที่เลิกใช้ และยกเลิก worker เมื่อออกจากเครื่องมือ โหมดคมชัดเก็บภาพแสดงผลเป็น PNG เพื่อคงสีดำ/ขาวโดยไม่มีรอยบีบอัด JPEG

ตรวจแล้ว: TypeScript, lint และ build ผ่าน ทดสอบสีและการแก้มุมรวม 6 กรณีผ่าน ครอบคลุมค่าระดับสีเทา การไม่แก้พิกเซลต้นทาง การแยกข้อความบนกระดาษที่มีแสงต่างกัน และขอบภาพขาวล้วน

ลองผ่านเบราว์เซอร์แล้ว: เปลี่ยนเฉพาะหน้า ใช้โหมดเดียวกันกับทุกหน้า คืนสีเดิมจาก URL ภาพสีเดิม แก้ขอบแล้วคงโหมด และยกเลิกงานพร้อมกัน 10 หน้าโดยทุกหน้ายังคงโหมดก่อนเริ่ม ยังต้องทดลองความชัดกับเอกสารถ่ายจริงและข้อความดินสอจางบนโทรศัพท์จริง

## ขั้นที่ 5 — ตัวอย่างและดาวน์โหลด PDF

- เพิ่มหน้าตรวจเอกสาร A4 เลื่อนดูทุกหน้าและกลับไปแก้ไขได้ โดยคงชื่อไฟล์และรูปแบบที่เลือกไว้
- จัดภาพให้พอดี A4 แนวตั้ง/แนวนอนตามภาพหลังหมุน มีขอบขาวอย่างน้อย 5 มม. และรักษาสัดส่วน
- ตั้งชื่อไฟล์ภาษาไทยได้ ปรับอักขระต้องห้ามและนามสกุลซ้ำให้อัตโนมัติ
- ส่งออก PDF รวมทุกหน้า หรือ ZIP ที่มี PDF หน้าละไฟล์เรียงชื่อ `-001`, `-002` ถ้ามีหน้าเดียวส่งออก PDF โดยตรง
- สร้างภาพส่งออกจากไฟล์ต้นฉบับที่ด้านยาวไม่เกิน 2,480 พิกเซล ประมวลผลขอบและโหมดสีใหม่ และคงการหมุนไว้
- ใช้ pdf-lib และ fflate ภายในเบราว์เซอร์ โหลดเป็นส่วนแยกเมื่อสร้างไฟล์ และเพิ่มไฟล์ที่ build ลงรายการ cache ของ PWA พร้อมขยับรุ่น cache เป็น v2
- แสดงความคืบหน้า ยกเลิกหรือกลับไปแก้หน้าได้โดยงานไม่หาย เมื่อไฟล์พร้อมแสดงขนาดจริงและปุ่มดาวน์โหลดที่ผู้ใช้กดเอง

ตรวจแล้ว: TypeScript, lint และ build ผ่าน ชุดทดสอบเกี่ยวกับเครื่องมือรวม 11 กรณีผ่าน ครอบคลุมตำแหน่ง A4, PDF หลายหน้า, ZIP ภาษาไทย, ชื่อไฟล์, หน้าเดียว และการยกเลิกระหว่างประกอบ PDF

ลองดาวน์โหลดจริงผ่านเบราว์เซอร์แล้วทั้ง PDF รวม, ZIP แยกหน้า และกรณีหน้าเดียว ตรวจด้วย pypdf พบ MediaBox เป็น A4 ตามแนวภาพ ลำดับ/ภาพใน ZIP ตรงกับ PDF รวม โหมดสีเทาและดำขาวถูกต้อง และภาพส่งออกจากเอกสารความละเอียดสูงมีด้านยาว 2,480 พิกเซล เรนเดอร์ PDF ด้วย Poppler และตรวจภาพแล้ว

ลองยกเลิกสร้าง PDF ขณะมี 10 หน้าแล้วไม่มีลิงก์ไฟล์ที่สร้างค้าง และกลับไปแก้ไขได้ครบทั้ง 10 หน้า ยังไม่ได้ทดลองการดาวน์โหลด/แชร์บน iPhone และ Android จริง หรือเปิดสร้าง PDF หลังปิดแอปแล้วเปิดใหม่ในโหมดเครื่องบิน

## ขั้นถัดไป — ตรวจบนอุปกรณ์จริงและออฟไลน์

ตรวจการเปิดกล้อง เลือกหลายภาพ ลากมุม ดาวน์โหลด/แชร์ไฟล์ การติดตั้ง PWA การอัปเดต cache และการเปิดใหม่ในโหมดเครื่องบิน บน iPhone, Android และคอมพิวเตอร์ รวมถึงภาพเอกสารจริงหลายสภาพแสง
