# ร่างระบบเครื่องมือสแกนเอกสารเป็น PDF

วันที่: 19 ตุลาคม 2569  
สถานะ: พัฒนาถึงขั้นตัวอย่างและดาวน์โหลด PDF แล้ว ดู [ความคืบหน้า](./document-scanner-progress.md)  
อ้างอิง: [แผนเดิม](./plan-document-scanner-to-pdf.md)

## 1. เป้าหมายและขอบเขต

ครูถ่ายหรือเลือกรูปเอกสารหลายหน้า ปรับขอบและความชัด จัดลำดับ แล้วดาวน์โหลด PDF ขนาด A4 ได้จากโทรศัพท์และคอมพิวเตอร์ เป็นเครื่องมือที่สองในหน้าเลือกเครื่องมือ ถัดจาก “กระดาษคำตอบ”

การประมวลผลภาพและสร้างไฟล์ทำในอุปกรณ์ ใช้งานออฟไลน์ได้หลังโหลดไฟล์แอปครบ งานสแกนเก็บชั่วคราวเฉพาะระหว่างเปิดเครื่องมือ เมื่อกลับหน้าเลือกเครื่องมือหรือรีเฟรชจะถูกล้าง ข้อมูลห้องเรียนและคะแนนของเครื่องมือเดิมยังใช้ IndexedDB ตามระบบปัจจุบัน และไม่มีการซิงก์ข้ามอุปกรณ์

รุ่นแรกมีการถ่ายภาพ เลือกรูปหลายภาพ จับขอบอัตโนมัติ ปรับมุมเอง หมุนภาพ โหมดภาพสามแบบ จัดลำดับหน้า ดูตัวอย่าง และส่งออก PDF รวม/แยกหน้า ส่วน OCR การแก้ข้อความในเอกสาร การนำเข้า PDF และประวัติงานสแกนเป็นงานนอกขอบเขตรุ่นแรก

## 2. เส้นทางและหน้าจอ

เส้นทางหลัก: หน้าเลือกเครื่องมือ → สแกนเอกสารเป็น PDF → เพิ่มเอกสาร → ปรับและจัดหน้า → ดาวน์โหลด

### หน้าเลือกเครื่องมือ

- เพิ่มการ์ด “สแกนเอกสารเป็น PDF” มีภาพและชื่อชัดเจน ใช้รูปแบบเดียวกับเครื่องมือเดิม
- เปิดได้โดยไม่ต้องสร้างพื้นที่ข้อมูลของเครื่องมือกระดาษคำตอบ
- มีปุ่มกลับหน้าเลือกเครื่องมือในทุกหน้าของเครื่องมือสแกน

### หน้าที่ 1: เพิ่มเอกสาร

เริ่มด้วยหัวข้อ “สแกนเอกสารเป็น PDF” และคำอธิบาย “ถ่ายหรือเลือกรูป แล้วบันทึกเป็น PDF”

ปุ่มหลักคือ “ถ่ายเอกสาร” และ “เลือกรูปจากเครื่อง” ปุ่มเลือกรูปรองรับหลายภาพ เมื่อมีภาพแล้วแสดงจำนวนหน้าและปุ่ม “ปรับและจัดหน้า” สามารถเพิ่มภาพภายหลังได้

กล้องใช้หน้าถ่ายภาพของอุปกรณ์ผ่านช่องเลือกไฟล์ที่แนะนำกล้องหลัง ส่วนคอมพิวเตอร์ใช้กล้องได้ตามความสามารถของเบราว์เซอร์และมีการเลือกรูปเป็นอีกทางเสมอ ต้องทดลองพฤติกรรมบนอุปกรณ์จริงระหว่างพัฒนา

### หน้าที่ 2: ปรับและจัดหน้า

บนคอมพิวเตอร์แสดงรายการภาพย่อด้านซ้าย ภาพหน้าที่เลือกตรงกลาง และเครื่องมือปรับภาพด้านขวา บนมือถือแสดงภาพใหญ่ ตามด้วยแถบเครื่องมือและรายการภาพย่อเลื่อนแนวนอน ปุ่มหลักอยู่ในตำแหน่งที่แตะได้สะดวกและไม่บังภาพ

เครื่องมือของแต่ละหน้า:

- “ปรับขอบ” เปิดภาพต้นฉบับพร้อมจุดมุมกระดาษ 4 จุด ลากได้ด้วยนิ้วหรือเมาส์
- “จับขอบใหม่” คำนวณขอบจากภาพต้นฉบับอีกครั้ง
- “หมุน” หมุนครั้งละ 90 องศา
- โหมด “สีเดิม”, “ขาวดำ” และ “ขาวดำคมชัด”
- “คืนค่าหน้านี้” กลับไปยังขอบและค่าภาพเริ่มต้น
- “ลบหน้า” และ “เพิ่มหน้า”

รายการภาพย่อแสดงเลขหน้า สถานะกำลังประมวลผล และหน้าที่เลือก เรียงด้วยการลากได้ พร้อมปุ่ม “เลื่อนก่อนหน้า/เลื่อนถัดไป” สำหรับมือถือและผู้ใช้คีย์บอร์ด หลังลบหน้าเลือกหน้าถัดไปหรือก่อนหน้าที่เหลือ เมื่อไม่เหลือภาพกลับสู่หน้าเพิ่มเอกสาร

การเปลี่ยนโหมดมีผลเฉพาะหน้าที่เลือก มีคำสั่ง “ใช้โหมดนี้กับทุกหน้า” แยกต่างหาก การหมุนและปรับขอบไม่กระทบหน้าอื่น

ปุ่ม “ดูตัวอย่าง PDF” เปิดหน้าดาวน์โหลดตามลำดับหน้าปัจจุบัน

### หน้าที่ 3: ดาวน์โหลด

- ดูตัวอย่างกระดาษ A4 พร้อมเลขหน้าและเลื่อนดูทุกหน้าได้
- กรอก “ชื่อไฟล์” ค่าเริ่มต้น `เอกสาร-YYYY-MM-DD` ตามวันที่บนอุปกรณ์
- เลือก “รวมทุกหน้าเป็น PDF เดียว” เป็นค่าเริ่มต้น หรือ “แยก PDF หน้าละไฟล์”
- แสดงจำนวนหน้าและขนาดไฟล์โดยประมาณหลังเตรียมข้อมูลภาพแล้ว
- ปุ่ม “ดาวน์โหลด PDF” หรือ “ดาวน์โหลด ZIP” เปลี่ยนตามรูปแบบที่เลือก
- มีปุ่ม “กลับไปปรับหน้า” โดยเก็บงานปัจจุบันไว้

แบบแยกหน้ารวม PDF ทุกไฟล์เป็น ZIP เพื่อให้ดาวน์โหลดครั้งเดียว ชื่อภายในคือ `ชื่อไฟล์-001.pdf`, `ชื่อไฟล์-002.pdf` ตามลำดับ หากมีหน้าเดียวให้ดาวน์โหลด PDF โดยตรง

หลังดาวน์โหลดยังคงงานไว้ให้แก้และดาวน์โหลดซ้ำ ปุ่ม “เริ่มงานใหม่” ล้างงานหลังยืนยัน เบราว์เซอร์บางเครื่องเปิดตัวอย่างหรือเมนูแชร์แทนการบันทึกทันที จึงแสดงคำแนะนำสั้น ๆ ตามผลที่เกิดขึ้น และไม่อ้างว่าบันทึกลงเครื่องสำเร็จจากการสร้างไฟล์เพียงอย่างเดียว

## 3. กติกาการปรับภาพ

1. อ่านภาพและทิศทางให้ถูกต้องก่อนสร้างภาพตัวอย่าง
2. ใช้ภาพย่อสำหรับค้นหาขอบ เพื่อลดเวลาประมวลผล
3. หากพบสี่เหลี่ยมกระดาษที่น่าเชื่อถือ ให้เสนอกรอบพร้อมภาพที่แก้มุมมองแล้ว
4. หากหาไม่พบ ใช้กรอบเต็มภาพและแจ้ง “ยังไม่พบขอบกระดาษ ลากมุมให้ตรงกับเอกสาร” ผู้ใช้ทำต่อเองได้
5. ตรวจไม่ให้กรอบไขว้กัน มีพื้นที่เล็กเกินไป หรือจุดหลุดนอกภาพ
6. แก้มุมมองจากมุมทั้งสี่ แล้วหมุนและปรับสีตามค่าของหน้านั้น
7. คำนวณจากต้นฉบับทุกครั้งเพื่อไม่ให้คุณภาพลดจากการแปลงซ้ำ

“สีเดิม” คงสีของภาพหลังแก้มุมมอง “ขาวดำ” เป็นระดับสีเทา และ “ขาวดำคมชัด” แยกพื้นกระดาษกับตัวอักษรด้วยเกณฑ์ที่ปรับตามบริเวณภาพ เหมาะกับเอกสารข้อความ แสดงตัวอย่างก่อนส่งออกเพื่อให้ผู้ใช้เลือกโหมดที่อ่านได้ดีที่สุด

ค่าตั้งต้นที่เสนอ: ประมวลผลภาพสำหรับส่งออกไม่เกินด้านยาวประมาณ 2,480 พิกเซล และใช้ JPEG คุณภาพประมาณ 0.85 โดยปรับภายหลังจากทดลองเอกสารจริง ตัวเลขนี้เป็นค่าทางเทคนิค ไม่ต้องแสดงในหน้าผู้ใช้

## 4. กติกา PDF

- ทุกหน้าเป็น A4 แนวตั้งหรือแนวนอนตามสัดส่วนภาพหลังหมุน
- วางภาพกึ่งกลางโดยรักษาสัดส่วนและให้เห็นเอกสารครบ ไม่มีการยืดหรือครอปเพิ่ม
- เผื่อขอบขาวเริ่มต้น 5 มม. ภาพจะมีขอบเพิ่มได้หากสัดส่วนต่างจาก A4
- ไฟล์รวมเรียงตามภาพย่อ ส่วนไฟล์แยกใช้ลำดับเดียวกัน
- ตัดช่องว่างส่วนเกินจากชื่อไฟล์ ป้องกันอักขระที่ใช้เป็นเส้นทาง และเติมนามสกุลให้ครั้งเดียว
- ปิดปุ่มสร้างไฟล์ระหว่างทำงาน พร้อมสถานะ “กำลังเตรียมหน้า 2 จาก 8” และให้ยกเลิกได้
- หากสร้างล้มเหลวคงภาพและค่าที่ปรับไว้ เพื่อให้ลองใหม่หรือกลับไปลดจำนวนหน้าได้

## 5. โครงสร้างโปรแกรม

แยกโมดูลใหม่ที่ `features/document-scanner/` เพื่อไม่ปะปนกับ `features/scanner/` ซึ่งอ่านกระดาษคำตอบ

| ไฟล์/ส่วน | หน้าที่ |
| --- | --- |
| `DocumentScanner.tsx` | คุมหน้าจอและวงจรงานทั้งหมด |
| `ImportPanel.tsx` | ถ่ายและเลือกภาพหลายไฟล์ |
| `PageEditor.tsx` | แสดงภาพและเครื่องมือของหน้าที่เลือก |
| `CropEditor.tsx` | ปรับมุมทั้งสี่และตรวจกรอบ |
| `PageList.tsx` | เลือก ลบ และจัดลำดับหน้า |
| `ExportPanel.tsx` | ตัวอย่าง ชื่อไฟล์ และตัวเลือกดาวน์โหลด |
| `session.ts` | เพิ่ม/แก้/ลบหน้า ลำดับงาน และล้างทรัพยากร |
| `image.worker.ts` | ค้นหาขอบ แก้มุมมอง และปรับสี |
| `image.ts` | อ่านภาพ สร้างภาพย่อ และจัดการทรัพยากรภาพ |
| `pdf.ts` | สร้าง PDF และ ZIP ภายในเบราว์เซอร์ |
| `types.ts` | ชนิดข้อมูลที่ใช้ร่วมกัน |

เชื่อมหน้าเลือกเครื่องมือด้วยสถานะเครื่องมือปัจจุบัน เช่น `null`, `answer-sheet`, `document-scanner` โดยตัวสแกนมี state ของตนเอง ไม่ต้องโหลดรายชื่อนักเรียนหรือชุดสอบก่อนใช้งาน

ประเมินการใช้โค้ดคำนวณเรขาคณิตจากตัวสแกนเดิมได้ แต่การจับกระดาษเอกสารทั่วไปต้องทำแยก เพราะไม่มีจุดอ้างอิงแบบกระดาษคำตอบ ไลบรารี PDF และ ZIP ให้เลือกตอนพัฒนา โดยต้องรวมไว้กับแอปเพื่อใช้ออฟไลน์ได้ ไม่โหลดจาก CDN ระหว่างใช้งาน

## 6. ข้อมูลงานชั่วคราว

แต่ละหน้ามี `id`, ภาพต้นฉบับ, ขนาดภาพ, จุดมุม 4 จุด, การหมุน, โหมดภาพ, ภาพย่อ, หมายเลขรุ่นของการแก้ไข และสถานะ `queued / processing / ready / error`

เก็บพิกัดมุมเป็นสัดส่วน 0–1 เทียบกับภาพต้นฉบับ เพื่อให้ใช้กับภาพย่อและภาพส่งออกได้ตรงกัน เก็บลำดับหน้าแยกจาก `id` และไม่บันทึกภาพเป็นข้อความ base64 ใน React state

งานระดับเครื่องมือมีรายการหน้า หน้าที่เลือก ขั้นตอนปัจจุบัน ชื่อไฟล์ รูปแบบส่งออก และสถานะกำลังสร้างไฟล์ ผลประมวลผลแต่ละงานต้องมีเลขรุ่น หากผู้ใช้ปรับค่าต่อระหว่างประมวลผล ให้ทิ้งผลเก่าที่มาถึงช้า

ประมวลผลทีละหน้าเป็นค่าเริ่มต้น เก็บภาพตัวอย่างขนาดเล็ก และสร้างภาพความละเอียดส่งออกตามต้องการ ปล่อย bitmap, canvas และ object URL เมื่อหมดใช้งาน ป้องกันการสะสมหน่วยความจำบนมือถือ

## 7. การออกจากเครื่องมือและข้อผิดพลาด

| เหตุการณ์ | พฤติกรรม |
| --- | --- |
| กลับหน้าเลือกเครื่องมือขณะมีภาพ | แจ้ง “ออกและล้างงานสแกนนี้?” มี “ทำต่อ” และ “ออกและล้างงาน” |
| รีเฟรชหรือปิดหน้า | ขอคำเตือนจากเบราว์เซอร์เมื่อรองรับ แต่ไม่พึ่งคำเตือนนี้ในการเก็บข้อมูล |
| สลับแอปแล้วกลับมา | ใช้งานต่อได้หากหน้าเดิมยังอยู่ในหน่วยความจำ |
| ไฟล์บางภาพเปิดไม่ได้ | ระบุชื่อภาพที่เปิดไม่ได้ และนำเข้าภาพที่เปิดได้ต่อ |
| ภาพ HEIC/รูปแบบที่อุปกรณ์อ่านไม่ได้ | แจ้งให้เลือก JPEG/PNG หรือถ่ายภาพใหม่ |
| หาแนวขอบไม่พบ | ให้ลากมุมเองและทำงานต่อได้ |
| ภาพเล็กหรือไม่ชัด | แจ้งให้ตรวจตัวอย่าง พร้อมเลือกใช้ต่อหรือเปลี่ยนภาพ |
| หน่วยความจำไม่พอ | หยุดงานที่ล้มเหลว คงหน้าที่พร้อมใช้ และแนะนำส่งออกเป็นชุดเล็กลง |
| ยกเลิกสร้างไฟล์ | กลับหน้าเตรียมดาวน์โหลดโดยคงงานเดิม |

เมื่อออกและล้างงาน ให้หยุด worker ยกเลิกงานค้าง และคืนหน่วยความจำทั้งหมด การส่งออกสำเร็จหมายถึงสร้างไฟล์และส่งต่อให้เบราว์เซอร์ได้ ไม่สามารถรับประกันว่าผู้ใช้บันทึกไฟล์ลงอุปกรณ์แล้ว

## 8. ออฟไลน์และหน้าตา

เพิ่มไฟล์ของเครื่องมือและ worker ในระบบ build/cache ของ PWA เดิม ให้หน้าเลือกเครื่องมือเปิดได้โดยไม่รอเครือข่าย ใช้ฟอนต์ ไอคอน และไลบรารีที่บรรจุมากับแอป แสดงสถานะออฟไลน์แบบสั้นโดยไม่ขัดขั้นตอนสแกน

ใช้สี ฟอนต์ ปุ่ม และระยะห่างจากเว็บปัจจุบันเป็นหลัก ปุ่มที่ใช้กับการลากมุมต้องมีพื้นที่แตะเพียงพอ สีกรอบตัดกับเอกสารชัดเจน มีป้ายชื่อและสถานะให้โปรแกรมอ่านหน้าจอ และควบคุมมุมด้วยคีย์บอร์ดได้บนคอมพิวเตอร์

## 9. ลำดับพัฒนา

1. เพิ่มทางเข้าเครื่องมือและหน้าจอพื้นฐาน พร้อม session ชั่วคราวและการล้างงาน
2. นำเข้าภาพหลายหน้า ภาพย่อ เลือกหน้า ลบ หมุน และจัดลำดับ
3. ทำกรอบสี่มุมและแก้มุมมองด้วยมือก่อน แล้วเพิ่มการจับขอบอัตโนมัติ
4. เพิ่มโหมดภาพและ worker พร้อมสถานะและการยกเลิก
5. สร้างตัวอย่าง A4, PDF รวม, PDF แยกใน ZIP และชื่อไฟล์
6. ผนวกกับ PWA และตรวจบนอุปกรณ์จริงตามเกณฑ์ด้านล่าง

## 10. เกณฑ์ตรวจรับเมื่อพัฒนา

- เปิดเครื่องมือใหม่จากหน้าเลือกเครื่องมือได้โดยไม่ต้องตั้งค่าข้อมูลของเครื่องมือเดิม
- ถ่ายเพิ่มหลายหน้าและเลือกหลายภาพได้ โดยกรณีไฟล์เสียไม่ทำให้ภาพอื่นหาย
- แก้มุม หมุน และเลือกโหมดภาพได้โดยไม่ทำให้ต้นฉบับเสียคุณภาพสะสม
- ลำดับและจำนวนหน้าในไฟล์ตรงกับตัวอย่าง ทั้งแบบรวมและแบบแยก
- เปิด PDF ที่ได้แล้วเป็น A4 ภาพไม่ถูกตัด อ่านได้ และชื่อไฟล์ภาษาไทยใช้งานได้
- ยกเลิกหรือสร้างไฟล์ล้มเหลวแล้วกลับมาแก้และลองใหม่ได้
- ออกและยืนยันล้างงานหรือรีเฟรชแล้วไม่เหลือภาพในงานใหม่
- ใช้งานผ่าน Safari บน iPhone, Chrome บน Android และเบราว์เซอร์คอมพิวเตอร์ได้
- เปิดใหม่และนำเข้าจนดาวน์โหลดได้ในโหมดเครื่องบิน หลังแอปและไฟล์ที่จำเป็นถูก cache ครบ
- ทดลองเอกสารข้อความ ภาพสี กระดาษเอียง พื้นหลังสีใกล้กระดาษ และแสงไม่สม่ำเสมอ
- ทดลองหลายภาพความละเอียดสูงบนมือถือ และปรับขนาดภาพ/การใช้หน่วยความจำจากผลจริง

ข้อเสนอในร่างนี้ที่เพิ่มจากแผนเดิมคือการหมุนภาพ การดาวน์โหลดไฟล์แยกผ่าน ZIP และขอบขาว 5 มม. ใช้เป็นค่าเริ่มต้นในการพัฒนาและปรับได้จากการทดลองใช้งาน
